# V2 input, arithmetic and lifecycle contract

Base input: exactly two UTF-8 basename CSV files, filename-indexed reported claims(period_amount,period_population,basis), initial region/window_start/window_end, authorized, source_read_budget, activity_budget, preparation_budget(default1), wake_delay_seconds, analysis_delay_seconds, interventions, repeat_scan. Existing fixtures.public_scenarios reproduces V1 exposed cases. fixtures.revised_scenarios and evidence_analyst_cases.json are new exposed inputs. Counts are lifetime ceilings across all revisions in a scenario; reservations are not refunded.

CSV columns exact set/count: event_id,region,occurred_at,ingested_at,amount. Unique nonempty IDs within each file; aware timestamps normalized UTC, ingestion not before occurrence. Region filtering happens before totals. Interval[start,end). All supplied region-matching records are summed; out-of-window records produce partial warnings rather than silent filtering. A is the uniquely declared occurred_at file, B ingested_at, independent of filenames. Same-ID conflicts compare region, normalized timestamps and numeric amount. Both raw conflicting rows remain in derived.csv. Unmatched A-only/B-only records must fit late-current/carry-in timing to reconcile; otherwise partial. Dataset completeness and business cause remain unknown.

Numeric limits: at most10000 data records per report; each amount spelling at most64 characters, finite, absolute value<=1000000000000, encoded decimal scale<=4 (Decimal exponent>=-4). Thus absolute report total<=1e16 and absolute difference<=2e16, at most22 significant decimal digits including four fractional places. Aggregation/difference use local precision32 independent of ambient Decimal context. Excess magnitude/scale/rows or malformed inputs reject without a current artifact. Scientific notation is accepted only within these same bounds. Excess precision encoded as trailing fractional zeros is also rejected, by design.

Intervention phases: before_wake(half initial delay), after_source_reads(after first analysis pair), while_scan_queued(at actual scan request). Existing operations cancel/revise/revoke/replace_file/fail_after_stage/new_source_claim/unrelated_event retain invalidation-only V1 meaning. New operation revise_and_reauthorize requires revision_kind='report_scope', complete scope{region,window_start,window_end}, complete updated claims for both filenames, renew_authorization=true, wake_delay_seconds and deadline_seconds. Claims are still reported, not read-verified. No re-labeling old claims to a new scope is permitted by the declared fixture contract. Unknown kind/missing scope/claims escalates and cancels current goal; missing renewed permission records revised intent but schedules no execution.

Supported revision clears old permission, cancels outstanding handles, closes old commitment as superseded, records new exact goal revision/roadmap/roles/commitment, waits for stale capability to finish under its revision fence, catches up MemoryProjector and records new scoped claims, drains/stops projection explicitly, records a new grant bound to exact revision/input allowlist/output/scope/due/deadline and schedules a real replacement timer. No source/read/preparation/activity counter is reset or refunded. Each scan offers at most one remaining activity to SDK; subsequent scans use remaining lifetime grant. Existing epoch terminal/preemption and fresh actual SDK selection are visible in canonical events.

Revision after two reads with initial8 read reservations,2 preparations,2 activities: old reservation4 stays spent; new reservation4 is admitted, measured total reads6, reservations8, preparations2, scans2. Initial4 ceiling cannot fund replacement even though only2 actual reads were consumed. Source changes or new_source_claim alone still invalidate without automatic renewal, and therefore remain potential missed feasible outcomes. Deadline expiry prevents current publication.

Output: trace.json carries canonical events, measured metrics, selections, current revision/status, current_artifact or null, commitment_status, real_wake_delay_seconds(first timer only), bus_errors. Each current_artifact records exact goal_revision, inquiry_id,selection_id,status(reconciled/partial),goal_fulfilled,scope,source_hashes,metrics and artifacts[{relative path,sha256,bytes}]. Metric amount strings use exact accepted Decimal arithmetic. ID sets include common_ids,a_only_ids,b_only_ids,late_current_ids,carry_in_ids,unresolved_ids; warnings disclose unresolved evidence. result.json additionally includes source records, scope, exact revision,idempotency key. derived.csv adds source_file,source_record(header-inclusive CSV record ordinal: header1/firstdata2, not physical line),source_sha256,membership,conflicting. Partial output may be current but cannot fulfill commitment.

Independent oracle must reopen bytes, recompute accepted arithmetic/hashes/row citations, audit publication prefixes and exact current revision, actual timer→scan/inquiry→selection→bridge→source reads→output readback→publication order, remaining budgets and permission. Staging is not publication. Correct cancellation/unsupported abstention, useful outputs, safe missed opportunities and false closures are separate outcome categories. A safe discard is not proof of changed-goal fulfillment. Timer cancellation is paired with revision fences; no durable restart scheduling claim.

Prefreeze input-hardening clarification: at most one revise_and_reauthorize request per scenario; multiple requests are rejected before application setup/effects (failed corpus entry). Supported scope region must be string/null, window strings aware and ordered, claims mappings with string period_amount/list-of-string population and exactly one occurrence/one ingestion basis. Explicit finite numeric wake_delay_seconds and deadline_seconds are required, with0<wake_delay<deadline; no defaults. Malformed/unknown single revisions record escalation and cancel current intent without a new artifact. This one-revision bound avoids unsupported concurrent renewal interleaving.
